# 知识库源数据（seed）

`knowledge/` 中 `01–10` 是原有电路与浮力知识文件，编号从 `011` 起的主题文件由本目录渲染。修改自动生成的主题时，在对应的 `*_kb.py` 里维护源数据。

## 一、为什么要有这一层

手工维护主题文件容易出现三类问题：

1. **格式漂移**——`kb.py` 靠 frontmatter 的 `主题` 做索引过滤、`类别` 做检索保底，少一个冒号整个主题就检索空；
2. **两处不一致**——同一个主题的关键词与核心公式，既写在知识库里，又写在 `topics.py` 的 PROFILE 里，手写必然对不上；
3. **维护重复**——批量修改同类内容需要分别更新多个文件。

所以源数据只写一份（`*_kb.py`），md 和 PROFILE 都从它生成。

## 二、文件分工

| 文件 | 作用 |
|---|---|
| `math_kb.py` 等 6 个 | 学科源数据：每个主题含课标/教材/规范/安全/交互五段 + 关键词 + 单位 + 公式 |
| `build_kb.py` | 渲染成 `knowledge/NNN_主题_类别.md`；保留既有编号，新主题追加编号；`--check` 只体检不写盘 |
| `build_topics.py` | 生成项目根的 `topics_extra.py`，由 `topics.py` 自动合并 |
| `check_kb.py` | 核对主题识别、求解器场景、五类知识包及跨主题检索 |

## 三、为什么是这五类

| 类别 | 写什么 | 谁用 |
|---|---|---|
| 课标依据 | 课标定位、学段、内容与学业要求 | 第 5 关教学审核（难度是否匹配） |
| 教材内容 | 核心概念、公式与结论、标准数据 | 生成器写页面正文与教学说明 |
| 实验规范 | 器材、步骤、操作要点、演示构成 | 生成器设计交互；J5 判步骤顺序 |
| 安全约束 | 数值边界、危险操作、禁止生成 | 第 1 关安全审查的直接依据 |
| 交互设计 | 可调参数、可复算量、常见错误 | 生成器设计滑块；审查器知道拿什么对拍 |

`交互设计 → 可复算量` 这一栏是最关键的：它把「这个页面该暴露什么数据」写成明确清单，
审查器 J1–J8 才有东西可算。没有这一栏，页面做得再漂亮也只能判 review。

## 四、新增一个主题

1. 在对应 `*_kb.py` 的 `TOPICS` 里加一条（照现有条目的字段写）；
2. `python seed/build_kb.py` —— 生成 5 个 md；
3. `python seed/build_topics.py` —— 更新 `topics_extra.py`；
4. `python seed/check_kb.py` —— 必须全过再往下走。

关键词要注意冲突：`detect_topic` 按关键词长度加权取最高分。同分时取字典里靠前的那条，
所以每个主题至少要有 1 个**别人不会用**的特征词（例：串并联用「串并联」，细胞结构用「细胞结构」）。

## 五、化学求解器与知识主题映射

| 求解器 | 必须命中的知识主题 |
|---|---|
| `CHEMSOLVER.balanceEquation` | 化学方程式配平 |
| `CHEMSOLVER.solveStoichiometry` | 反应计量与限量试剂 |
| `CHEMSOLVER.solveSolutionMixing` | 溶液混合与反应计量 |
| `CHEMSOLVER.solveAcidBaseTitration` | 酸碱中和滴定 |
| `CHEMSOLVER.solveGasCollection` | 气体制取与集气定量 |
| `CHEMSOLVER.solvePrecipitation` | 沉淀反应定量 |
| `CHEMSOLVER.solveRedox` | 氧化还原方程式配平 |
| `CHEMSOLVER.solveSolubilityEquilibrium` | 溶解平衡与 Ksp |

分离提纯和分子模型两个化学专用页面场景也分别有独立知识主题。`check_kb.py` 会扫描场景注册表，
核对每个求解器 API 是否存在相应主题与五类知识，并用代表性需求跑完真实的主题识别和知识包组装。

## 六、物理求解器与知识主题映射

| 物理场景 | 对应知识主题 |
|---|---|
| 直流电路 | 电路、伏安法测电阻、串并联电路 |
| 光学与波 | 凸透镜成像、折射与全反射、平面镜成像、波的传播与声速 |
| 热学与流体 | 浮力、液体压强、比热容 |
| 运动与受力 | 匀变速直线运动、平抛运动、一维受力与摩擦 |
| 功、能与简单机械 | 杠杆平衡、功与功率、机械能变化与守恒、斜面、滑轮组 |

`physics_solver_kb.py` 保存新增场景的源数据，每个主题包括课标、教材、规范、安全与交互五类内容。教学模型的参数、单位和对照实验按已接入的求解器和浏览器变形用例编写。学段定位参照教育部发布的课程标准。 [义务教育课标](https://www.moe.gov.cn/srcsite/A26/s8001/202204/t20220420_619921.html?fromColId=204) [普通高中课标](https://www.moe.gov.cn/srcsite/A26/s8001/202006/t20200603_462199.html)

`python 02_retrieval_agent/seed/check_kb.py --physics` 按场景注册表检查全部物理求解器，用代表性需求验证主题识别、求解器选择和五类知识包。

## 七、数学求解器与知识主题映射

`math_solver_kb.py` 的 `SOLVER_TOPICS` 列出 39 个已接入求解器与变形测试的数学场景。二次函数、平面截正方体、正方体展开、勾股定理、平均数与方差沿用已有主题，其余 34 个场景各有一组独立知识条目。

每组按教学范围记录可复算示例、交互参数、输入边界和变形关系。例如，有限抽样分别核对放回与不放回时的概率，三视图投影核对等比缩放下的投影面积和体积。学段与领域参照课程标准，公式示例和交互边界按 ICT 场景编写。 [义务教育数学课标](https://www.moe.gov.cn/srcsite/A26/s8001/202204/t20220420_619921.html) [普通高中课标](https://www.moe.gov.cn/srcsite/A26/s8001/202006/t20200603_462199.html)

在项目根目录运行 `python -B 02_retrieval_agent/seed/check_kb.py` 可检查代表性教学需求是否选中对应求解器、识别正确主题并组装五类知识。

## 八、一个坑

`knowledge/` 下的**所有** `.md` 都会被 `kb.py` 加载。不要把 README、草稿、笔记放进去——
没有 frontmatter 的文件会被归到「通用 / 未分类」，污染全库检索结果。文档就放这个目录。
