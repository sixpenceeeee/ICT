# 组块化说明（PageSpec + 组件树）

这份文档说明生成端的组件化结构：**页面不再由每个场景手写渲染代码，而是由
「一份结构化描述 + 一组已登记组件」装配出来。**

## 一句话

```
PageSpec（页面是什么） → 组件树（页面怎么拼） → 六区内容 → shell 套壳 → 单文件 HTML
```

同一份 PageSpec 同时决定三件事，所以三方不可能漂移：

| 谁 | 从 PageSpec 拿到什么 |
|---|---|
| 渲染器 | 控件、读数、图例、文案、组件开关 |
| 生成端硬校验 | `data-solver-input` / `data-solver-field` 等标记清单 |
| 审查端 | 求解器 API、`__PREFIX_REQUEST__/__RESULT__` 取证变量、变形关系 |

## 为什么改

改造前，一个场景的契约被复制到 6 个地方，加一个实验要改 6 处，漏一处就是
"能生成但审查判死"：

| 位置 | 原来负责什么 |
|---|---|
| `scene_registry.py` | 自然语言契约 + 求解器 API |
| `solver_templates.render_solver_template` | 一串 `if scene_id == ...` |
| `generator_agent.generate` | 又一串 `if scene_id == ...`（5 段近乎逐字重复） |
| `generator_agent.hard_validate` | 117 条 `problems.append` 手写标记检查 |
| `checks_browser.js` | 又一份标记清单 |
| 每个渲染器 | 自己拼六区 HTML + 内联 CSS + 自己写运行时脚本 |

改造后只有一个来源：`scene_catalog.py`（场景表）+ `page_spec.py`（页面描述）
+ `components/`（组件实现）。

## 目录

```
03_generator_agent/
├── page_spec.py           PageSpec：构造 / 校验 / 标记推导 / 取证 token
├── scene_catalog.py       场景表：场景 -> (渲染器种类, 模型, UI 元数据) + 覆盖率体检
├── generic_lesson.py      唯一的 lesson 渲染器：PageSpec -> 六区（无学科分支）
├── components/
│   ├── atoms.py           原子组件（控件、读数卡、表格、按钮、图例、说明）
│   ├── controls.py        ③ 区：控件组 + 预设条 + 动作按钮
│   ├── readouts.py        ④ 区：读数卡 + 代入式 + 错误态 + 对照面板
│   ├── records.py         ⑤ 区：记录表
│   ├── stage.py           ② 区：画布 + 图例
│   ├── teaching.py        ① / ⑥ 区：学科胶囊 + 学习目标 + 教学说明
│   ├── runtime.py         页面运行时（唯一一份脚本：控件→请求→求解→绑定→绘图→记录）
│   └── registry.py        组件登记表 + 六区装配
├── page_components.py     兼容层（旧渲染器照旧 import，拿到的是同一份原子组件）
└── tests/test_componentization.py
```

## 契约怎么保证不漂移

1. 组件渲染时**同时返回它产出的标记**（`Rendered.markers`）；
2. `page_spec.markers(spec)` 从 spec 推导出一份期望清单；
3. `generic_lesson._check_contract` 在渲染后立刻核对：spec 声明的标记与取证 token
   必须真的落在页面里，缺一个就抛 `SceneNotRenderable`，**不出半成品页**；
4. 测试再双向核对一次（标记 ⊆ 页面、页面 ⊆ 标记），并且用生成端同一套
   `hard_validate` 复验。

## 新增一个场景要做什么

**情况 A：模型已在 `lesson_models.json`，且有共享绘图函数**

1. 在 `scene_catalog.UI` 加一条（标签、单位、范围、预设中文名、图例、代入式、教学文案）；
2. 在 `scene_catalog.SCENE_RENDERERS` 加一条 `{"renderer": "generic", "model": ..., "subject": ...}`。

不需要改渲染器、不需要改硬校验、不需要改运行时脚本。

**情况 B：有求解器但没有绘图函数**

先补共享绘图组件（`frame/phys.js` 里的 `PHYS.xxx(cv, request, result)`），再按 A 登记。
在补之前，`python -m scene_catalog` 会把这个场景列为"需补组件"并说明缺什么——
生成端不会悄悄产出"只有数字没有实验对象"的页面。

**情况 C：化学组件模板 / 数学套装 / 早期物理模板**

在 `CHEM_TEMPLATES` 或 `SCENE_RENDERERS` 里登记后由 `scene_catalog.render_scene` 统一分发。


## 单位换算约定

PageSpec 里所有数值都是**求解器单位（SI）**；控件显示单位由 `ui.inputs[name].scale`
声明（例如体积 `scale=1e-6`：控件显示 cm³，请求里是 m³）。运行时负责双向换算，
所以读数卡、记录表、代入式里的数字永远同源同单位。

- `physics_page_templates._lesson_script` 保留同名薄包装，内部调用 `components.runtime`；
  三个早期物理模板的六区输出逐字不变。

  仍由 `scene_catalog.render_math_scene` 分发。
- 六个化学组件模板未改动，只是从 `generate()` 里的 5 段重复分支收进 `CHEM_TEMPLATES` 表。
