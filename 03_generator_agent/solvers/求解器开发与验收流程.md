# 求解器开发与验收流程

后续增加学科求解器时，按这套流程推进。目标是让求解器结果实际约束生成页面，并能由独立审查复算，而不只是给页面增加一段“正确性说明”。

## 1. 定义问题边界

- 说明求解器解决什么问题、接收什么输入、返回什么结果。
- 明确当前支持和不支持的情况；不确定或超范围输入应明确报错，不能猜答案或回退手写结果。
- 列出必须成立的学科不变量，例如守恒、节点方程、几何闭合或概率和为 1。

## 2. 定义结构化数据契约

- 用稳定的 JSON 对象表达问题，不让求解器从任意页面文案里猜关键参数。
- 为请求和结果设置固定字段、单位、取值范围和版本标识。
- 结果包含可复核的中间量和 `checks`，让错误能定位到具体约束。

## 3. 实现确定性求解内核

- 关键科学计算由确定性算法完成，大模型负责把教学需求映射到结构化输入并组织说明。
- Python 版本作为独立参考实现；网页端 JavaScript 版本供单文件离线页面运行。
- 关键结果使用解析式或精确计算；浮点运算则声明容差和适用范围。

## 4. 接入场景骨架和生成约束

- 在场景注册表中按学科与主题选择求解器。
- 提示生成器把数据契约、调用顺序和失败处理要求交给页面生成 Agent。
- 生成硬校验检查是否真实调用求解器、是否暴露请求/结果、显示值是否读取同一个结果对象。
- 求解失败时显示错误状态，不显示看似正常的示意结果。

## 5. 接入独立质量审查

- 浏览器检查器读取页面实际暴露的请求、结果和关键显示内容。
- 审查器使用 Python 参考实现重新计算，再与页面结果逐项对拍。
- 设计独立复算时，优先从不同的学科约束或计算路径推出结果。比如从动量平衡反推维持静止所需的摩擦冲量，或先算平均功率，再从功率—时间图的有符号面积复算功。
- 为每个题型选一个容易写错的判断，构造能区分正确与错误实现的成对输入。用真实浏览器改控件，再故意提交该错误的结果，确认专项复算和变形测试能拦住。
- 不把页面自报的 `checks.ok=true` 当作独立证据。
- 关键结果不一致或无法复算时，判定失败并阻止交付。

## 6. 分层验收

- **正例**：典型题、常见复杂输入、不同参数。
- **反例**：错误输入、守恒不成立、无解、多解和范围外情况。
- **边界**：零值、极值、退化结构、单位/格式变化等适用边界。
- **跨实现对拍**：同一输入下 Python 参考实现与 JavaScript 页面端结果一致。
- **系统接线**：主题能选中骨架，单文件 HTML 能自动内联求解器，审查器能抓住故意篡改的结果。
- **浏览器验收**：在真实浏览器运行，确认无脚本错误、可见值与结果一致、输入变化能更新结果。

## 7. 交付时说明范围

报告测试数量、通过/失败情况、浏览器验收情况，以及明确的能力边界。求解器通过不等于大模型生成的整份页面已经端到端验收；如需验收完整交付物，还要另跑生成流水线和页面质量审查。
