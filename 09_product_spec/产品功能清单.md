# 产品功能清单（终版）

## 一句话

> 老师用**一句话**描述想上的实验或知识点，系统在 30 秒内生成一个**可离线运行**的互动教学页面，并自带一份**质检报告**；不合格自动重写。

---

## 0. 这个产品到底是什么

不是"聊天机器人"，也不是"课件生成器"。它是一个**带质检闭环的教学资源生产线**：

```
一句需求  →  四道工序  →  一个能上课的页面 + 一份质检报告
```

三条设计原则，决定了后面所有功能取舍：

1. **产物必须是单文件 HTML**。教室没网也能开，U 盘拷走就能用，不依赖任何服务器。
2. **生成结果绝不直接交付**。必须过质检，不合格自动带意见重写。
3. **凡是视觉上呈现的东西，都要同时给出机器能复算的表征**。否则审查器只能验"有没有"，验不了"对不对"。

---

## 1. 四层结构

| 层 | 面向谁 | 回答什么 |
|---|---|---|
| 入口层 | 老师 | 怎么把需求交给系统 |
| 生成层 | 系统 | 一句话怎么变成一页课件 |
| 产出层 | 老师 | 拿到什么、能不能改 |
| 平台层 | 赛事 / 运维 | 跑在哪、怎么扩容、怎么演示 |

## 4. 三条边界（必须主动说，别等评委问）

1. **不评价开放表达**。作文文采、口语发音、审美鉴赏不做——没有可复算判据，硬做只会产出"满分但没用"的页面。这类应该走对话型 Agent，是另一套逻辑。
2. **不做真实实验操作指引**。化学只做虚拟仿真，不给"取 50 mL 浓硫酸倒入水"这类真实操作步骤；不做市电接入。
3. **不追求覆盖全部知识点**。只做**有确定性判据**的内容：153 条清单里 11 条已明确判"不做"，其中 8 条换一种题型范式可救回（如"心脏结构标注"→ 标注 + 因果链）。

这条边界不是能力不足，是**质量承诺**：宁可不做，也不交付一页看着热闹、实际算错的课件。

## 6. 距离"能交"还差三件事

按顺序，不能并行：

| 顺序 | 做什么 | 对应功能 | 判断标准 |
|---|---|---|---|
| 1 | **一个网页界面** | F01 F03 F13 F15 | 老师不碰命令行，点两下出结果 |
| 2 | **上 AgentArts** | F17 F18 F19 | 平台里点"运行"，跑出同样的页面 |
| 3 | **演示物料** | F21 | 3 分钟视频：一句话进 → 页面出 → 质检报告出 |

界面放在最前面，理由很实际：**F17 之后本地代码会变成"平台配置"，再想改界面就来不及了**。界面先在本地做，结构照着 AgentArts 工作流的四个节点摆，迁移时一比一对应。

## 7. 一页速览（给评委看的版本）

| 环节 | 老师看到什么 | 系统做了什么 |
|---|---|---|
| 输入 | 打一句话："做一个能调电阻和电压的电路实验" | 理解成 8 个结构化字段 |
| 检索 | —— | 从教材知识库里召回 12 段相关知识 |
| 生成 | 等 20 秒 | 写出一页含滑块、电路图、数据表的 HTML |
| 质检 | 看到 91 分 | 真浏览器打开、拖滑块、复算公式，找出 3 个问题 |
| 返工 | —— | 带着问题清单重写，第 2 轮 98 分 |
| 交付 | 下载一个 HTML 文件 | 单文件、离线、可投影 |

**核心差异**：别人交付"生成结果"，我们交付"生成结果 + 可验证的质量证据"。
